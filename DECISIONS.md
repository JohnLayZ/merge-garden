# Decisions

- Vite `base` defaults to `./`; CI sets `BASE_PATH` to the repo name for GitHub Pages.
- ESLint (flat config) forbids DOM globals and `Math.random` in `src/game/` to keep logic pure.
- jsdom is not needed for game logic; localStorage persistence takes an injectable storage interface.
- Playwright runs with the pre-installed Chromium at /opt/pw-browsers/chromium when present (config falls back to Playwright's own download elsewhere). Added @playwright/test as devDependency.
- GitHub Pages: workflow builds with BASE_PATH=/<repo-name>/ (vite.config.ts reads it, default './'). Triggered on push to main; Pages source must be set to GitHub Actions once in repo settings (cannot be done from here).
- ~~Watering a plant gives no score and does not count as a merge; it can be undone like a move. Cans beyond the cap of 3 are lost.~~ (entfernt in Paket 5, siehe unten)
- A "double spawn" (2 seeds) happens with 10% probability, otherwise 1 seed.
- Level 7 plants never merge with each other.
- ~~Game is "lost" only if the board is blocked AND no can can upgrade any plant.~~ (entfernt in Paket 5: verloren = Feld voll und keine Verschmelzung mehr möglich)

## Änderungsrunde 4 (Paket 3: Spielzeit, Sounds)
- Play time is part of the saved game as `GameState.playMs` (not part of the undo snapshot, so undo never rewinds time). Old saves without it load as 0. Pure logic in `src/game/timer.ts` (`TimerState`, `resumeTimer`, `pauseTimer`, `elapsedAt`, `shouldRun`, `formatTime`); every function takes the clock as a parameter. `main.ts` feeds it `performance.now()`, so wall-clock changes or the gap between two page loads never count.
- The timer runs only while `shouldRun`: first valid move happened (`moves > 0`), status `playing`, page visible. On `visibilitychange` and `pagehide` the time is summed up and saved; while running it is saved about every 5 s as a crash safety net. After a win/loss the stored value is final, so the overlay time stays frozen across reloads.
- Header got a third box "Time"; the overlay shows an extra line "Time: m:ss". Points 1 and 2 of the order share one commit because both touch the same view/state code.
- E2E adjustments (no test weakened): the page now saves on `pagehide`, which overwrote localStorage seeded via `page.evaluate` before a reload, so win tests seed the position with `addInitScript` before the app loads. The "reload keeps the game state" test ignores the `playMs` digits in the raw storage string, because the time legitimately advances between the two snapshots.
- Sounds: own module `src/audio/sound.ts` (Web Audio, no files, no dependency); game logic is untouched. Context is created lazily by `unlock()` on the first pointerdown/keydown/touchstart. Volume: master gain 0.12, only sine/triangle, 25 ms attack, exponential decay. Merge notes: C major pentatonic C4 D4 E4 G4 A4 C5 for resulting levels 2–7 (the tone of a multi-merge move follows the highest new level); level >= 4 adds an octave overtone, level >= 6 a fifth. Decision: no sound for plain moves ("gar keines"), as it would repeat constantly. Water: two soft rising notes *(Gießkannen-Klang entfernt in Paket 5)*; win: short arpeggio C5–E5–G5–C6 plus a chord; game over: two gently falling triangle notes (F4 → D4, not minor/heavy). End of game replaces the merge/water sound.
- Mute button in the header (inline SVG icons, `aria-pressed`), state in `localStorage` key `merge-garden:muted`. Default is sound on. Audio or storage failures are swallowed so the game never breaks.
- SPEC.md: the non-goal "kein Sound" was dropped and the animation/feel line updated.
- Release flow and order documentation are now rules in CLAUDE.md.

## Änderungsrunde 5 (Paket 4: Lautstärke, Icon, Branch-Löschung)
- **Lautstärke (Sounds waren am Handy zu leise, Tester brauchte ~75 % Gerätelautstärke):** Es gibt jetzt eine zentrale Konstante `MASTER_VOLUME` in `src/audio/sound.ts`. Jede Tonspitze ist `relativer Gain × MASTER_VOLUME`; alle relativen Gains stehen in `GAINS` und sind ≤ 1 (per Test geprüft). `MASTER_VOLUME` wurde von 0,12 auf **0,30** angehoben (Faktor 2,5, Ziel war 2–3×).
- Zusätzlich läuft alles über einen `DynamicsCompressor` als Begrenzer am Ausgang (threshold −12 dB, knee 6, ratio 12, attack 3 ms, release 250 ms), damit überlagerte Töne (Sieg-Akkord, Merge mit Obertönen) nicht übersteuern oder knacken. Statt die Einzelwerte weiter anzuheben, ist der Pegel so über einen Wert nachjustierbar.
- Verhältnis der Sounds zueinander bleibt wie bisher (Merge 1, Gießkanne 0,8/0,7, Sieg 0,9/0,5, Game Over 0,7; Obertöne 0,35/0,3). Wellenformen, Tonhöhen, Dauer und Ein-/Ausklingen unverändert, also nichts schärfer oder schriller.
- Wahrnehmung beim Verschmelzen: höhere Töne wirken bei gleichem Pegel lauter (Gehör, Obertöne). Deshalb wird der Merge-Gain nach Stufe leicht abgesenkt: Stufe 2: 1,00; 3: 0,97; 4: 0,90; 5: 0,85; 6: 0,80; 7: 0,74 (Obertöne skalieren mit). Vorher waren alle Stufen 1,0.
- Spitzenwerte (Gain am Oszillator, vorher → nachher): Merge Stufe 2 0,120 → 0,300; Stufe 4 0,120 → 0,270; Stufe 7 0,120 → 0,222; Gießkanne 0,096/0,084 → 0,240/0,210; Sieg-Arpeggio 0,108 → 0,270, Sieg-Akkord 0,060 → 0,150 je Ton; Game Over 0,084 → 0,210.
- Der bestehende Test "Spitze ≤ 0,2" wurde nicht gelöscht, sondern auf die neue Obergrenze `MASTER_VOLUME` umgestellt (die Obergrenze ist jetzt die zentrale Konstante). Neu: Gains ≤ 1, alle Tonknoten laufen über den Begrenzer, Stumm-Schalter schaltet alle vier Sounds ab.
- **Branch-Löschung:** Regel in CLAUDE.md: Branch nach dem Merge mit demselben GitHub-Werkzeug löschen wie der Merge (nicht `git push --delete`), höchstens ein Wiederholungsversuch, sonst im Abschlusstext melden und auf "Delete branch" im gemergten Pull Request verweisen.
- **README-Link:** Platzhalter `<owner>` durch https://johnlayz.github.io/merge-garden/ ersetzt.
- **Icon:** `public/icon.svg` (Spross aus `level2-sprout.svg` auf pastellgrünem, abgerundetem Quadrat, gleiche Konturfarbe `#4e6b4e`, Erdschatten). PNGs 192/512 liegen in `public/` und werden per `dev/make-icons.mjs` (Playwright, nur Dev-Werkzeug, keine neue Abhängigkeit) aus dem SVG erzeugt. Alles in `public/` landet unverändert in `dist/`; `index.html` verweist mit `/icon.svg` usw., Vite setzt dabei die Basis davor (`./` lokal, `/merge-garden/` auf Pages); das Manifest nutzt relative Pfade (`icon-192.png`, `start_url: "./"`). Manifest: Name/Kurzname "Merge Garden", `display: standalone`, `background_color #fffdf5` (Seitenhintergrund), `theme_color #cfe8cf` (Spielfeldgrün), dazu `theme-color`-Meta und `apple-touch-icon`. Kein Service Worker. Test `tests/icons.test.ts` baut `dist/` mit beiden Basen und prüft Dateien, PNG-Größen, Manifest und die Links in `index.html`. Sichtprüfung per Screenshot (512 px, 192 px, 60 px, 32 px): scharf, nichts abgeschnitten, keine Nachbesserung nötig.

## Änderungsrunde 6 (Paket 5: Regeln und Stufen)
- **Gießkanne entfernt (Punkt 1):** Die Einträge zur Gießkanne weiter oben bleiben als Historie stehen und sind mit „entfernt in Paket 5“ markiert. Grund: Wunsch des Spielers, die Gießkanne ist keine Spielregel mehr. Entfernt wurden Logik (`useWateringCan`, `earnCans`, `cans`, `mergeCount`, `MAX_CANS`, `MERGES_PER_CAN`), Oberfläche (Button, Anzeige, Auswahlmodus, CSS), der Klang `water`, `src/assets/drop.svg` und alle zugehörigen Tests. Verloren ist das Spiel jetzt, wenn das Feld voll ist und keine Verschmelzung mehr möglich ist. Undo bleibt (ein Schritt, nach Sieg/Game Over gesperrt).
- **Spielstand-Version:** Der gespeicherte Spielstand trägt jetzt `version` (`SAVE_VERSION = 2` in `src/storage.ts`, gleicher Storage-Key `merge-garden:v1`). Ein Stand ohne oder mit anderer Version (also alles aus der Zeit vor Paket 5) wird verworfen, es startet ein neues Spiel; der Highscore wird aus dem alten Stand übernommen (`loadGame` liefert dann `{ state: null, best }`). Nötig, weil sich Stufenzahl und Zustandsfelder ändern. Künftige Formatänderungen erhöhen die Zahl.
- **9 Stufen, zentrale Liste (Punkte 2 und 3):** `src/levels.ts` enthält `LEVELS` (Name, SVG, Feldfarbe, Größe je Stufe) und `MAX_LEVEL = LEVELS.length`. `types.ts` re-exportiert `MAX_LEVEL`; Spiellogik, Speicher-Validierung, Tests und UI lesen die Stufenzahl nur daraus (die Liste liegt bewusst nicht in `src/ui/`, damit `src/game/` nicht von der UI abhängt; sie enthält nur Daten). Die Siegstufe ist immer die letzte Stufe: eine weitere Stufe braucht nur einen neuen Listeneintrag samt SVG (und `SAVE_VERSION` erhöhen). Feldfarben stehen nicht mehr im CSS, sondern kommen aus der Liste (per `--tile-bg` am Feld). Die vorhandenen SVGs (Seed bis Flower, Tree, Ancient Tree) sind inhaltlich unverändert, nur die Dateien für Tree/Ancient Tree wurden umbenannt (`level7-tree.svg`, `level9-ancient-tree.svg`). Neu: `level6-young-tree.svg`, `level8-old-tree.svg`.
- Größen (`PLANT_SCALE`): 0,30 / 0,38 / 0,46 / 0,54 / 0,62 / 0,70 / 0,80 / 0,88 / 0,95 (streng steigend, neun Werte). Neue Feldfarben: Junger Baum `#f6efc6` (zartes Gelb), Alter Baum `#d6dff3` (zartes Blau); die übrigen Farben unverändert.
- Punkte unverändert (Verschmelzung zu Stufe n = 2^n; Sieg bei Stufe 9 = 512 Punkte im letzten Zug). Samen bleiben Stufe 1, gelegentlich zwei Samen (10 %) bleibt. Der Sieg (Punkt 3) tritt jetzt erst bei Stufe 9 ein; Stufe 7 (Tree) und 8 (Old Tree) beenden das Spiel nicht. Kein Weiterspielen nach dem Sieg, wie bisher.
- **Optik-Prüfung (Punkt 4):** Screenshots von `dev/plants.html` (520 px und 360 px) und des laufenden Spiels bei 360 px mit allen 9 Stufen gleichzeitig auf dem Feld angesehen. Nichts ist abgeschnitten, alle Pflanzen sind auf ihren Pastellfeldern gut lesbar, Bush und Flower sind klar verschieden. Nachgebessert: (a) Der erste Entwurf des Alten Baums sah dem Uralten Baum zu ähnlich (gleiche dunkle Krone mit Querband); jetzt etwas hellere Krone (`#76c093`, aber weiterhin dunkler als der Baum), das Querband entfällt, andere Blattstriche; Früchte, Wurzeln und Astloch gibt es weiterhin nur beim Uralten Baum. (b) Junger Baum von Skala 0,70 auf 0,72, damit er neben der Blume nicht zu klein wirkt. Seed ist bei 0,30 klein, aber (wie schon in Paket 2 entschieden) lesbar; das SVG bleibt unverändert. Die Vorschau zeigt jetzt alle 9 Stufen in einem 4-Spalten-Raster (die untere Kante der letzten Zeile ragt nur in der Vorschau über das Brett hinaus, weil dort kein Spielfeld-Seitenverhältnis erzwungen wird).
- **Längenabschätzung (Punkt 5):** `dev/simulate.ts` (Start: `npm run simulate [-- Anzahl]`, über `dev/simulate.mjs` mit Vites SSR-Lader, keine neue Abhängigkeit, nicht im Produktions-Build) spielt mit der echten Spiellogik 500 Partien (Seeds 1000–1499). Strategie: nach unten, sonst links, sonst rechts, zuletzt oben. Ergebnis (nur zur Orientierung, **keine Regeländerung**): Siegstufe (Ancient Tree, Stufe 9) in nur 12 von 500 Partien (2,4 %); Züge bis zum Ende (Sieg oder Niederlage) Mittel 220,3, Median 204; bis Stufe 7 (454 Partien erreichten sie) Mittel 99,4, Median 98; bis Stufe 8 (241 Partien) Mittel 176,1, Median 176; bis Stufe 9 (12 Partien) Mittel 292,8, Median 286,5. Die einfache Strategie ist weit schlechter als ein menschlicher Spieler; der Sieg ist damit schwer, aber nicht ausgeschlossen. Ohne Gießkanne bleibt keine Hilfe gegen ein volles Feld.
- **Sounds für 9 Stufen (Punkt 6):** `src/audio/sound.ts` leitet `MERGE_NOTES` und `GAINS.mergeByLevel` aus `MAX_LEVEL` der Stufenliste ab (Merges erzeugen die Stufen 2 bis `MAX_LEVEL`; Stufe 1 entsteht nur durch Spawn und hat keinen Klang). Töne: C-Dur-Pentatonik (C D E G A, jede Oktave wiederholt) ab C4, eine Note je Stufe: Stufe 2–7 unverändert C4 D4 E4 G4 A4 C5, neu Stufe 8 = D5 (587 Hz), Stufe 9 = E5 (659 Hz; der Sieg spielt ohnehin den Sieg-Jingle statt des Merge-Tons). Gain: linear von 1,0 (Stufe 2) auf 0,6 (letzte Stufe), also 1,00 / 0,94 / 0,89 / 0,83 / 0,77 / 0,71 / 0,66 / 0,60 für Stufe 2–9 — streng fallend, nie unter 0,6 und für Stufe 3–7 etwas leiser als die alte Kurve (0,97 … 0,74 war höher), also nie lauter. Damit höhere Stufen nicht schriller werden, entfallen Obertöne über 1046,5 Hz (der höchste Oberton vor Paket 5); das betrifft nur die Oktave bei Stufe 8 und 9. `MASTER_VOLUME` (0,30) und der Begrenzer sind unverändert. Neue Tests: für jede Merge-Stufe existieren Ton und Gain in 0,6–1 (Ton steigt, Gain fällt), Spitze ≤ `MASTER_VOLUME`, alle Töne laufen über den Begrenzer, keine Obertöne über der Grenze.
- **Branch-Regel (Punkt 7):** CLAUDE.md korrigiert: Der Agent kann Branches nicht selbst löschen (das GitHub-Werkzeug hat keine entsprechende Funktion), das Löschen übernimmt die Repo-Einstellung „Automatically delete head branches“. Neue Regel: Branch nach dem Merge nicht selbst löschen, im Abschlusstext nur erwähnen, falls er danach noch existiert. Die Paket-4-Regel (Löschen per MCP, ein Wiederholungsversuch, „Delete branch“-Hinweis) ist damit ersetzt.
